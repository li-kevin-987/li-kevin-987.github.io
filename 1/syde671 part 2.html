Cropping is done in 3 steps:

First, remove the white outer border. This is done by simply taking the average brightness of each row in the image, then looking for the first row from the top that has a lower average brightness than a certain cutoff, and removing all rows above that one. The same is done from the bottom up (remove all rows below the first row from the bottom that is below the brightness cutoff), and from the left and right for the image's columns.

Next, a constant crop is done on each side of the image. This is done because the scan itself is not always exactly angled correctly, and thus the transition from white to black is often not perfectly horizontal. This leads to a few rows/columns between the white and black borders that are part-white and part-black, which can't be easily removed by using a naive method of taking the average brightness of a row/column.

Finally, step 1 is repeated for the inner black border, removing all rows/columns outside the first row/column that is above a certain brightness cutoff.

Cropping is done for the original image, then for each of the three component images to remove the black region in between images (in this case, the first step usually shouldn't crop anything).

Cropping for the white background seems to generally work well in my experience, but it works worse for the black region since there is often stains/writing/white spots on the black region, which causes problems for the naive average-brightness solution I'm using. I haven't seen any catastrophic failures, though, so I think it's good enough.

def crop(image, white_cutoff, black_cutoff):
  img_height = len(image)
  img_width = len(image[0])

  # white background crop
  row_means = np.mean(image, axis=1)
  top = 0
  for row in range(img_height):
    avg_shade = row_means[row][0]
    if avg_shade < white_cutoff:
      break
    top += 1

  bottom = img_height
  for row in range(img_height - 1, -1, -1):
    avg_shade = row_means[row][0]
    if avg_shade < white_cutoff:
      break
    bottom -= 1

  image = image[top:bottom]

  col_means = np.mean(image, axis=0)

  left = 0
  for col in range(img_width):
    avg_shade = col_means[col][0]
    if avg_shade < white_cutoff:
      break
    left += 1

  right = img_width
  for col in range(img_width - 1, -1, -1):
    avg_shade = col_means[col][0]
    if avg_shade < white_cutoff:
      break
    right -= 1

  image = image[:, left:right]

  # extra crop to remove remaining white due to picture not being fully aligned
  extra_crop = img_height // 300

  image = image[extra_crop:-extra_crop, extra_crop:-extra_crop]

  # black background crop
  img_height = len(image)
  img_width = len(image[0])
  row_means = np.mean(image, axis=1)

  top = 0
  for row in range(img_height):
    avg_shade = row_means[row][0]
    if avg_shade > black_cutoff:
      break
    top += 1

  bottom = img_height
  for row in range(img_height - 1, -1, -1):
    avg_shade = row_means[row][0]
    if avg_shade > black_cutoff:
      break
    bottom -= 1

  image = image[top:bottom]

  col_means = np.mean(image, axis=0)

  left = 0
  for col in range(img_width):
    avg_shade = col_means[col][0]
    if avg_shade > black_cutoff:
      break
    left += 1

  right = img_width
  for col in range(img_width - 1, -1, -1):
    avg_shade = col_means[col][0]
    if avg_shade > black_cutoff:
      break
    right -= 1

  image = image[:, left:right]

  return image

Image contrast balance is done very simply, just take the maximum and minimum brightness value of all pixels in an image, and rescale all the pixel values by the formula $x = (x - \text{min}) * \frac{255}{\text{max} - \text{min}}$. This is done for each of the 3 color components of the image.

In [3]:
def contrast_balance(image):
  image_max = np.max(image)
  image_min = np.min(image)
  scale = 255 / (image_max - image_min)
  offset = image_min
  image = (image - offset) * scale
  return image

I tried implementing both euclidean distance and normalized cross correlation. For both, the pattern I followed for transforming the second image is to pad it to the shape of the first image if it is shorter in the x or y axis, then apply the offset, then crop it to the size of the first image if it is larger in the x or y axis. (The first image is, in practice, always the blue channel of the image). There is a reason that I chose to do it this way (explained at the end of the page), but it ended up not mattering because of the next step (which I didn't consider doing until I read the tips section of the assignment):

After modifying the second image, a constant ratio of rows/columns are cropped from the edges of both images, before calculating the underlying metrics. The functions themselves don't return the exact metrics for optimization reasons, but they do return values that result in the same ordering as if the exact metrics were used (explained better in the code itself).

def euclidean_distance(image1, image2, x_offset, y_offset):
  image2 = np.pad(image2, ((0, max(0, image1.shape[0] - image2.shape[0])),
                           (0, max(0, image1.shape[1] - image2.shape[1]))))
  image2 = np.roll(image2, (x_offset, y_offset), axis=(1, 0))
  image2 = image2[:image1.shape[0], :image1.shape[1]]

  # remove border region
  border_crop_0 = image1.shape[0] // 20
  border_crop_1 = image1.shape[1] // 20
  image1 = image1[border_crop_0:-border_crop_0,border_crop_1:-border_crop_1]
  image2 = image2[border_crop_0:-border_crop_0,border_crop_1:-border_crop_1]

  # return negative sum since align function optimizes for highest score
  # (don't need to sqrt since we only care about optimization instead of
  #  actual distance)
  return -np.sum(abs(image1 - image2), dtype = np.float64)

def normalized_cross_correlation(image1, image2, x_offset, y_offset):
  image2 = np.pad(image2, ((0, max(0, image1.shape[0] - image2.shape[0])),
                           (0, max(0, image1.shape[1] - image2.shape[1]))))
  image2 = np.roll(image2, (x_offset, y_offset), axis=(1, 0))
  image2 = image2[:image1.shape[0], :image1.shape[1]]

  # remove border region
  border_crop_0 = image1.shape[0] // 10
  border_crop_1 = image1.shape[1] // 10
  image1 = image1[border_crop_0:-border_crop_0,border_crop_1:-border_crop_1]
  image2 = image2[border_crop_0:-border_crop_0,border_crop_1:-border_crop_1]

  # don't need image1 norm since we're only searching over possible offsets of
  # image2 (so image1 norm is constant)
  image2_norm = np.linalg.norm(image2)

  return np.sum(np.multiply(image1, image2, dtype=np.float64)) / image2_norm

I designed a wrapper function to combine the BGR images using any align function (either single scale or multi scale, and using any arbirtrary scoring function). An optimal offset is calculated for the green and red images, and layered onto the original blue image.

Note that the final image has color channels B, G, R. On Google Colab, this displays incorrectly (it expects the order to be R, G, B), but this is the correct order for the cv2.imwrite function, for some reason.

def combine(image_b, image_g, image_r, align, output_file):
  offset_g, metric_g = align(image_b, image_g)
  offset_r, metric_r = align(image_b, image_r)

  print("Offset for green:", offset_g)
  print("Offset for red:", offset_r)

  image_g = np.pad(image_g, ((0, max(0, image_b.shape[0] - image_g.shape[0])),
                             (0, max(0, image_b.shape[1] - image_g.shape[1]))))
  image_g = np.roll(image_g, offset_g, axis=(1, 0))
  image_g = image_g[:image_b.shape[0], :image_b.shape[1]]

  image_r = np.pad(image_r, ((0, max(0, image_b.shape[0] - image_r.shape[0])),
                             (0, max(0, image_b.shape[1] - image_r.shape[1]))))
  image_r = np.roll(image_r, offset_r, axis=(1, 0))
  image_r = image_r[:image_b.shape[0], :image_b.shape[1]]

  final_image = np.stack([np.round(image_b), np.round(image_g), np.round(image_r)], axis=-1).astype(np.uint8)
  cv2.imwrite(output_file, final_image)
  return final_image

def single_scale_align(image1, image2, range_x, range_y, metric):
  best_metric = -float("inf")
  best_offset = (0,0)
  for x_offset in range_x:
    for y_offset in range_y:
      result = metric(image1, image2, x_offset, y_offset)
      if result > best_metric:
        best_metric = result
        best_offset = (x_offset, y_offset)
  return best_offset, best_metric

For multi scale alignment, I made a function that accepts an initial x and y range for the smallest scale image, and a number of scales that determines the height of the image pyramid.

Downsampling is simply done by taking only every $2^n$-th row and 2^n$-th column at scale $n$ (with scale $0$ being the full original image).

In terms of search, the function chooses the best offset at each scale, multiplies it by 2 to translate it to the same pixel on the next scale, and then searches a 5x5 square around that pixel.

In [9]:
def multi_scale_align(image1, image2, range_x, range_y, num_scales, metric):
  image1_downsample = image1[::2**(num_scales-1), ::2**(num_scales-1)]
  image2_downsample = image2[::2**(num_scales-1), ::2**(num_scales-1)]
  best_metric = -float("inf")
  best_x = -1
  best_y = -1
  for x_offset in range_x:
    for y_offset in range_y:
      result = metric(image1_downsample, image2_downsample, x_offset, y_offset)
      if result > best_metric:
        best_metric = result
        best_x = x_offset
        best_y = y_offset
  for scale in range(num_scales-2, -1, -1):
    best_x *= 2
    best_y *= 2
    image1_downsample = image1[::2**scale, ::2**scale]
    image2_downsample = image2[::2**scale, ::2**scale]
    best_metric = -float("inf")
    for x_offset in range(best_x - 2, best_x + 3):
      for y_offset in range(best_y - 2, best_y + 3):
        result = metric(image1_downsample, image2_downsample, x_offset, y_offset)
        if result > best_metric:
          best_metric = result
          best_x = x_offset
          best_y = y_offset

  return (best_x, best_y), best_metric

I decided the number of scales for each image using the formula $\text{num_scales} = \lfloor \log_2(\text{image width}) - 5\rfloor$, so that the smallest scale image will be relatively constant for any scale of image. The constant 5 is arbitrary, and was selected because it worked best for the dataset in practice.

def full_pipeline(image, output_file):
  cropped_image = crop(image, 240, 50)

  img_height = len(cropped_image)
  img_width = len(cropped_image[0 ])

  img_b = cropped_image[0:img_height//3]
  img_g = cropped_image[img_height//3:-img_height//3]
  img_r = cropped_image[-img_height//3:]

  cropped_b = contrast_balance(np.max(crop(img_b, 240, 40), axis=2))
  cropped_g = contrast_balance(np.max(crop(img_g, 240, 40), axis=2))
  cropped_r = contrast_balance(np.max(crop(img_r, 240, 40), axis=2))

  num_scales = int(np.log2(img_width) - 5)

  ms_align_w_params = lambda a,b: multi_scale_align(a, b, range(-3,4), range(-3,4), num_scales, normalized_cross_correlation)
  return combine(cropped_b, cropped_g, cropped_r, ms_align_w_params, output_file)

*Note on the way that image2 is manipulated in the euclidean distance and normalized cross correlation function:

I did it this way because I wanted to somewhat mitigate spurious "matches" matching the right/bottom parts of the second image to the left/top of the first image. Doing it this way makes it so that if the second image is smaller than the first image, then more of the columns/rows rolled over to the other side will be padding columns/rows (which are all black). This doesn't fully solve the problem, as when image2 is larger than/equal size to image1 there is still the possibility of these spurious "matches", and even when it is smaller, a big enough offset will still cause this issue. Since the edges of both images are cropped out afterwards, though, none of this ends up mattering.
